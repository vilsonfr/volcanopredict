# Contribuindo

1. Abra uma issue antes de mudanças grandes.
2. Para código, crie uma branch `feature/...` ou `fix/...`.
3. Inclua testes para lógica nova.
4. Não inclua tokens, senhas ou chaves de API.
5. Toda fonte externa deve ser registrada no catálogo de fontes.
6. Para modelos científicos, documente hipótese, variáveis, período de treino/teste e incerteza.
7. Nunca apresente um score como alerta oficial de emergência.

Áreas de contribuição:
- Go/backend
- React/Cesium
- geoprocessamento/PostGIS
- ciência de dados/estatística
- fontes de dados vulcanológicos e sísmicos
- meteorologia e dispersão de cinzas
- tsunami
- atividade solar/geomagnética
- documentação e UX
